# Provenance

- **Provenance.** The run loop attaches a `ProvenanceRecorder` (`server/src/provenance/recorder.ts`) to the same `session.subscribe` stream the SSE mapper reads, and appends one observed step per tool call to `sandbox/.kady/provenance/<sessionId>/steps.jsonl`. Rows are **derived from observation, never model declaration** — there is deliberately no agent-facing tool that writes here, because provenance is what you check the model against. `write`/`edit`/`read` name their file (edges `observed`); `bash`/`subagent`/unknown tools are opaque and get a bounded stat-only sandbox scan-diff (`server/src/provenance/scanner.ts`), whose edges downgrade to `inferred` when a neighbouring step finished before the scan ran. Scans are async-drained so the event handler never blocks SSE for other tabs; `flush()` in the run's `finally` drains before the terminal frames. Budgets (20k files, 512MB/file hash, 200 edges/step) degrade *visibly* — `sandbox-too-large`/`scan-failed`/`unhashed`/`truncatedEdges` — since silent truncation reads as a verified absence of outputs. `server/src/provenance/lookup.ts` inverts the log by path for `GET /sandbox/provenance`, computing staleness (current/stale/unknown) and flagging notebook citations written before an artifact's latest version. Subagent work is harvested from each child's session JSONL on completion (`server/src/provenance/harvest.ts` + `bridge.ts`, same `tool_result`/`subagent:async-complete` hooks as the notebook harvest and cost ledger) and appended to the parent's log with `role: "subagent"` and the child's agent name/model — no tool is installed in the child, so it stays unauthorable. Because that work is inspected *after* it finished, harvested refs are marked `identityAt: "harvest"` (a matching hash then proves only "unchanged since we looked", so `lookup.ts` reports `unknown`, never `current`), `change` is `wrote` rather than a created/modified guess, and a child's opaque `bash` gets `degraded: "no-scan-baseline"` plus optional mtime-window `inferred` edges filtered by already-claimed paths. Three further step sources join the same log: **user steps** (`server/src/provenance/user-steps.ts`, `role: "user"`, pseudo-session `user-actions`) are recorded by the sandbox routes for upload/save/move/delete so lineage chains have a root and an editor save is a recorded producing step rather than an unexplained "stale"; **compute steps** (`modal-steps.ts`, `role: "compute"`, id `modal:<jobId>`) are written at the Modal manager's single terminal transition from the transfer layer's own staging/collection hashes (observed, write-time — no harvest caveat); and every lead step carries an **`environmentId`** pointing at a content-addressed snapshot in `.kady/environments/` (`environment.ts`: venv `pyvenv.cfg` + `dist-info` names with no subprocess, one bounded `Rscript` probe when present, lockfile hashes, git HEAD), captured at run start and re-captured when an install-shaped command ran or the stat fingerprint of lockfiles + venv changed (`uv.lock` and `.venv` are invisible to the scan, so the diff alone misses `uv run` syncing a venv); harvested steps get a harvest-time snapshot marked `environmentAt: "harvest"`. Opaque calls also get `inferred` **input** edges from files their command line names that existed beforehand and were not written (`mentions.ts`), which is what lets `lookup.ts`'s `walkLineage` walk figure → script + table → upload; the walk is version-aware (producer at-or-before the consuming step) and reports `changedSinceUse` per upstream node. Tests that build a `ProvenanceRecorder` should pass `captureEnvironment: false` (or a stub) so they do not spawn probes. Not yet covered: nested (depth > 1) subagents, remote image package enumeration — see `docs/provenance.md`.
