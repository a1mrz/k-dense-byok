# HTTP boundary and sandbox guards

- **The HTTP boundary is `request-guard.ts` + `auth.ts`, not CORS.** The backend is an unauthenticated-by-default API that can run a shell, so the first `onRequest` hook refuses a disallowed `Origin` (preflights included — CORS alone never stops a cross-site `<form>` POST), a `Host` that could be DNS-rebound (only loopback names, IP literals, the machine hostname, `KADY_ALLOWED_HOSTS`), and a no-cors subresource load (`Sec-Fetch-*` with no Origin) whose `Referer` is not the UI. Trusted UI origins are the UI port only (`KADY_FRONTEND_PORT`, default 3000) on loopback/own-interface hosts plus `KADY_ALLOWED_ORIGINS` — never "any localhost port", because the agent starts local servers that serve untrusted HTML. An `onSend` hook gives every response `Content-Security-Policy: sandbox; default-src 'none' …` (PDFs exempt) + `nosniff` + `Referrer-Policy: no-referrer`, because `/sandbox/raw` serves untrusted HTML/SVG from the API origin. `auth.ts` enforces an access token (`X-Kady-Token`, bearer, or `kady_token` query — redacted from logs) when the backend binds beyond loopback or `KADY_REQUIRE_AUTH=1`; the web side is `web/src/lib/api-auth.ts` (`apiFetch` header, `withApiToken()` for every URL the browser loads itself — new `<img>`/download/pdf.js URL builders must use it) and `ApiTokenGate`; child packages send `process.env.KADY_AUTH_TOKEN`. Side-effecting routes must not be GETs (`/mcp/status` is POST for this reason). Values persisted to `.env` must pass `invalidEnvValue` (a newline would add a `NODE_OPTIONS=` line); custom-model keys go through `encodeApiKeyForPi` (Pi runs `!cmd` and expands `$VAR`); LaTeX compiles with `latexmk -norc`. See `docs/security.md`.

- **Raw-data guard.** `server/src/agent/data-guard.ts` is a `tool_call` hook (registered after the subagent bridge so budget gates run first) that blocks `write`/`edit`/`bash` mutations of the project's protected globs (`sandbox/.kady/policy.json`, `guard-policy.ts`, default `user_data/**`) and, when `destructiveConfirm` is on, pauses destructive shell commands elsewhere via `permissions.ts`: a `permission_request` frame rides the run's `RunHandle`, the UI answers through `POST /sessions/:id/permissions/:requestId`, and abort/run completion/10-min timeout resolve it as a block. The classifier (`bash-classifier.ts`: segment split, `cd` tracking, redirects, mutating verbs, destructive patterns, benign `rm -rf` targets) is pure and copied byte-for-byte into `server/pi-packages/kady-guard/classifier.ts` for child processes (`bash-classifier.test.ts` runs the same table against both and asserts parity); the child package blocks destructive commands outright since it has no UI. `sandbox-seed.ts` now versions `AGENTS.md` (`AGENTS_MD_HISTORY`; v7 scopes uv to the local sandbox and resolves distributions before import repairs): a sandbox whose file equals an older shipped version verbatim is upgraded on the next seed pass, an edited file is left alone and reported by `agentsMdStatus`, and `restoreAgentsMd` is the explicit restore. Heuristic, not a security boundary — see `docs/data-guard.md`.

- **Local shell trust boundary.** Agent tools run as the current OS user and are not an OS-level secret boundary. Kady-scoped `auth.json` is protected from other users, not from same-user shell processes. New sandbox instructions forbid reading credentials, but use a container/VM/separate account for adversarial content; see `docs/limitations.md`.
