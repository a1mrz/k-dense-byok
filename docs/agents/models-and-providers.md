# Models, providers, credentials, pricing

- **Models.** `server/src/agent/models.ts` resolves canonical `provider/model` refs (`openrouter/<vendor>/<model>`, `ollama/<name>`, `openai-compatible/<id>`, or `<pi-provider>/<model-id>` for every other built-in Pi provider) to a Pi `Model`, synthesizing OpenRouter models from `web/src/data/models.json` pricing when not built in. **Every Pi provider is supported** (https://pi.dev/docs/latest/providers): `server/src/agent/provider-catalog.ts` is the single table of direct API-key / cloud-credential providers (Anthropic, OpenAI, Google, Vertex, Azure, Bedrock, Cloudflare ×2, NVIDIA NIM, Groq, Cerebras, Mistral, DeepSeek, Hugging Face, Fireworks, Together, Baseten, Vercel AI Gateway, OpenCode ×2, Kimi, Moonshot ×2, MiniMax ×2, Z.AI ×2, Qwen ×3, Xiaomi ×4, Ant Ling, Meta) with the env var(s) Pi reads, a billing class, and Settings field metadata; `provider-auth.ts` lists the OAuth logins (OpenAI / Sign in with ChatGPT, OpenAI Codex (legacy), Anthropic, GitHub Copilot, xAI, Kimi For Coding, Meta Muse, OpenRouter, Radius). `openai`/`anthropic`/`xai`/`kimi-coding`/`meta` appear in both — one ref, and billing follows whichever credential Pi resolves; `openai-codex`/`github-copilot`/`radius` stay OAuth-only (`isOAuthOnlyProvider`). Direct refs are never split after the prefix (NIM, Hugging Face, Fireworks, Cloudflare `@cf/…` ids contain slashes) and resolve only through Pi's registry — an unknown id is an error, except NVIDIA NIM, whose ids are synthesized at $0 like Pi's own entries (`synthesizeUnknownIds`; a payg model synthesized at $0 would bypass the spend cap). Pi renames a provider id now and then (1.0.3: `azure-openai-responses` → `azure`); saved refs and session files keep the old id, so `canonicalProviderId` (`RENAMED_PROVIDERS` in `provider-catalog.ts`) maps it before resolution. `provider-catalog.test.ts` checks the catalogue against the live runtime: every Pi provider covered, names match, and setting only the declared env vars flips `checkAuth` (providers with no chat models, e.g. TypeSafe's classifier-only catalogue, are exempt) — so a Pi upgrade that renames a variable fails a test instead of leaving a dead Settings field.

- **App defaults.** Settings → Defaults (`web/src/components/settings/defaults-panel.tsx`) stores the model, thinking level and compute a project's *first* chat tab starts on, the `verifierModel` reviewer specialists run on (see the verification caveat), plus `generate_image`'s `imageModel` (read on every call, so it applies to open chats; only per-token output-priced models are accepted or listed by `GET /settings/image-models`; an unavailable saved model falls back to `DEFAULT_IMAGE_MODELS` with a note in the tool result), in `<KADY_PI_AGENT_DIR>/kady-settings.json` (`server/src/app-settings.ts`, `GET/PUT /settings/defaults` in `api/app-settings.ts`; malformed file → 409, never rewritten; unknown top-level keys survive). A tab opened next to an existing one still copies that tab's choices; only the model is consumed server-side. Precedence in `configuredDefaultRef()` / `resolveModel(undefined)` (hence system runs with no project model to reuse): saved default → env `DEFAULT_MODEL_PROVIDER`/`DEFAULT_MODEL_ID` → built-in; a saved default that no longer resolves falls back silently so sessions stay openable. `fusion/…` refs are refused (they only resolve with the browser-sent panel config).

- **Fusion pricing.** `buildFusionModel` prices a turn as each panel model once **plus the judge twice** — OpenRouter bills "N panel calls + 1 judge call in addition to your normal request", and under the `openrouter/fusion` alias that fusion-bridge.ts always sends, the judge also writes the final answer. The multiplier (`JUDGE_CALLS_PER_TURN`) and the judge accessor exist twice, in `server/src/agent/models.ts` and `web/src/lib/fusion-presets.ts`, because the picker quote and the ledgered price must agree; `server/test/fusion-pricing.test.ts` has a parity check over the shipped presets. Partly-priceable configs still run (under-counting, flagged in the picker); only a wholly unpriceable one throws.

- **Local model servers.** Two parallel discovery paths, deliberately not factored together: Ollama (`/ollama/models` → `OLLAMA_BASE_URL/api/tags`) and any OpenAI-compatible server (`/openai-compatible/models` → `OPENAI_COMPATIBLE_BASE_URL/v1/models`, default LM Studio's `:1234`). The latter's picker section stays hidden unless the env var was set (`configured`) or a server answers. Both URLs are live: `config.ts` exposes getters (`ollamaBaseUrl()`, `openaiCompatibleBaseUrl()`, `openaiCompatibleConfigured()`) read per call rather than import-time constants, and `api/credentials.ts` manages them as non-secret fields (`ollamaBaseUrl`, `openaiCompatibleBaseUrl`, echoed unmasked, http(s) `validate` hook) whose `onChange` calls `registerLocalProviders()` (`agent/models.ts`), so Settings → Providers → Local model servers applies without a restart and clearing one falls back to the default. Only `id` is read from `/v1/models`; refs are `openai-compatible/<id>` and may contain slashes, so only the prefix is stripped. Both providers are billed `local`/$0 in `cost/billing.ts`, `cost/ledger.ts`, and `agent/subagent-bridge.ts` — that trio must stay in sync or a local run defaults to `payg` and counts against the spend cap. Local-only by design: a hosted gateway would need real pricing, so route those through `OPENROUTER_BASE_URL` instead.

- **Outbound proxy.** `server/src/http-proxy.ts` installs undici's `EnvHttpProxyAgent` as the global dispatcher at boot (`index.ts`, `isMain` block) when `HTTP_PROXY`/`HTTPS_PROXY` is set, and is a no-op otherwise. Node's fetch ignores those variables on its own (`NODE_USE_ENV_PROXY` is Node ≥ 24 and we support ≥ 22.19), and Pi's `configureHttpDispatcher` isn't in the package's public exports — without this the lead agent would dial providers directly while the subagent runner honoured the proxy. Note undici tunnels with `CONNECT` even for `http://` targets.

- **Provider authentication contract.** `ProviderAuthManager` passes Pi's `LoginOptions.getDeviceId`, backed by `SettingsManager.getOrCreateDeviceId()` in the global agent directory, for current ChatGPT sign-in. Do not promote `.env` keys to `setRuntimeApiKey`: that overlay masks stored OAuth and is invisible to child runtimes. Pi's stored credential wins over environment keys; an explicit Settings key save removes the previous stored credential to select environment-key auth. Clearing an environment key preserves an independent OAuth login and writes empty `.env` assignments (including aliases) so stale shell/legacy keys do not reappear at restart. `setupModelRuntime` normalizes `OR_API_KEY` into the inherited `OPENROUTER_API_KEY`. `/model-providers.configured` describes effective key-or-OAuth availability; `connected` describes OAuth specifically. Real-Pi callback/manual-login regressions with mocked token exchanges live in `server/test/provider-auth-integration.test.ts`. Pi 1.0's Anthropic login opens with a `select` prompt (browser vs. copy-code, for a browser on another machine than the backend), which the generic prompt bridge and the OAuth dialog already carry. Anthropic also authenticates by workload identity federation (`ANTHROPIC_FEDERATION_RULE_ID` + `ANTHROPIC_ORGANIZATION_ID` + `ANTHROPIC_IDENTITY_TOKEN_FILE`, optional service-account/workspace ids) when no key is set; they are non-secret `extraEnv` fields of the catalogue entry.

- **Thinking level.** Each chat tab has a per-run thinking-level selector (`web/src/components/thinking-selector.tsx`, default `high`); the run body's `thinkingLevel` is validated by `server/src/agent/thinking.ts` and applied via Pi's `session.setThinkingLevel()` after `setModel`. Ollama and Fusion runs send no level (chip disabled). Caveat: like `setModel`, Pi's `setThinkingLevel` also persists the value as the **global default** in the configured Pi agent directory (`~/.kady/pi-agent/settings.json` by default), so the last level picked in any tab becomes the starting level for subagent child `pi` processes. It also affects the user's standalone Pi CLI only when `PI_CODING_AGENT_DIR` was explicitly shared. Pin a `thinking` level in a specialist's frontmatter if a subagent must not inherit it.

- **Model billing.** OpenRouter cost is read from Pi's `usage.cost` (computed from `model.cost`); synthesized model pricing comes from `web/src/data/models.json`. Pi-documented Anthropic OAuth metered extra usage also counts toward caps. OpenAI Codex, GitHub Copilot, and xAI OAuth usage records tokens/reference price without counting it as project spend; this is not a claim that provider usage is free, because quotas and overages are managed externally. NVIDIA NIM and the prepaid token plans (`qwen-token-plan*`, `xiaomi-token-plan-*`; `isPlanBilledProvider` in `provider-catalog.ts`) are classified the same way (`billingMode: "subscription"` despite being API-key-based): they bill provider-managed credits or a plan quota rather than per-token USD, Pi prices every such model at $0, and treating them as payg would let an exceeded spend cap block runs that ledger $0 (`provider-catalog.test.ts` asserts an all-$0 Pi catalogue is plan-billed and a mostly-priced one is not). Every other direct provider is payg with Pi's list price. OpenRouter/Radius OAuth logins are `payg` (they stand in for a key); the Kimi Code OAuth login is `subscription` while `KIMI_API_KEY` is payg. Picker rows carry the same `billingMode` from `directModelForClient`, and `/providers/models` skips a dual provider Pi resolved via OAuth so each model is listed once, under the billing its credential implies.

- **One-shot model calls must name a reasoning level.** Methods draft (`agent/methods-draft.ts`), What next? proposals (`agent/next-experiments.ts`) and editor LaTeX assist (`latex/assist.ts`) call `ModelRuntime.completeSimple(model, context, { maxTokens, reasoning: ONE_SHOT_REASONING })` (`agent/one-shot-reasoning.ts`), not `complete`. `complete` is the raw provider stream: with no effort given, Pi's OpenAI-compatible adapter sends OpenRouter `reasoning: { effort: "none" }` for every reasoning-capable model, and models whose reasoning cannot be disabled (GPT-6 Astra, the default) answer `400 Reasoning is mandatory for this endpoint and cannot be disabled` — chats were unaffected because a session always carries the tab's thinking level. `completeSimple` clamps the level to what the model supports, so the one constant is safe for non-reasoning models too. The three tests assert the option is passed.

- **Custom model servers (`models.json`).** `server/src/agent/custom-models.ts` manages Pi's `<KADY_PI_AGENT_DIR>/models.json` (`GET/PUT /custom-models`, Settings → Providers → Custom model servers): validation (`CUSTOM_PROVIDER_ID_RE`, no collision with catalogue/OAuth/reserved ids, http(s) base URL, api ∈ openai-completions|openai-responses|anthropic-messages, models with optional USD-per-million cost), atomic write, then `ModelRuntime.refresh()` so the new provider is live without a restart. Kady rewrites only providers it created (sidecar `kady-custom-models.json`); hand-written providers are listed read-only and a same-id save is refused. `directProviderRef` in `models.ts` recognizes custom ids via `isCustomProvider` (mtime-cached) so `<id>/<model>` resolves through `registry.find` and an unknown id errors — the legacy "unknown prefix = OpenRouter vendor id" fallback is kept for stored refs. `/providers/models` appends custom rows (`sourceLabel: "Custom servers"`, `billingMode: "payg"`, declared cost) and lists the provider as configured, so the picker and `billing.ts` (payg default) agree. Keyless servers get `apiKey: "none"`, like Kady's own Ollama registration. `modelThinkingLevels` is deliberately not exposed (the tab's thinking level is applied after `setModel`).

- **Provider refusals are explained, not swallowed.** Anthropic's Mythos-class models classify the *whole* request before generating; Claude Fable 5 refuses outright when the skills index in the system prompt carries certain seeded scientific skills (`adaptyv`, `diffdock`, `ginkgo-cloud-lab`, `glycoengineering`, `pathogen-variant-surveillance`, `phylogenetics`, `tamarind` — each verified to refuse on its own description, 2026-08-27). The wire signal is `stop_reason: refusal` / OpenRouter `finish_reason: content_filter` with **no `usage` object at all**, which is why such a run reports zero input tokens and bills nothing. It is a model-level behaviour reproducible with a bare chat-completions call, not a Kady bug, and it hits the lead agent as well as subagents (children inherit the lead's model). `server/src/agent/model-refusal.ts` recognizes the signal and builds the guidance; `events.ts` forwards the provider's own `errorMessage` rather than a generic `Model error`, `api/sessions.ts` appends the guidance to both provider-error publish points, and `makeSubagentRefusalExtension` appends it to a refused child's `subagent`/`bg_wait` result — a child dies in its own session inside pi-subagents' runner process, so runner text is the only trace that reaches the parent. `KNOWN_REFUSAL_TRIGGER_SKILLS` is used **only** to make an error message specific: never to block, disable, or filter, because it is empirical and providers retune classifiers. See `docs/limitations.md`.
