# Sandbox API, scientific previews, Office

- **Sandbox API + scientific previews.** `server/src/api/sandbox.ts` ports all file ops (tree/read/write/move/upload/zip/raw/download), annotation sidecars, LaTeX compile (async latexmk/multi-pass with SyncTeX), `/sandbox/synctex` (source<->PDF mapping), and the budget-gated `/sandbox/latex-assist` one-shot AI endpoint (ledgered under session id `latex-assist`). LaTeX assist returns a discriminated `status: replacement|needs_context`; only replacements enter diff review, and incomplete/malformed model responses are rejected after recording incurred usage. It also serves rich previews for many scientific formats. The frontend has an extensible viewer registry: `web/src/lib/viewers/registry.ts` maps a `FileCategory` (`web/src/lib/use-sandbox.ts`) to a lazy-loaded viewer in `web/src/components/viewers/*`; `FileViewer` in `file-preview-panel.tsx` checks the registry first and falls back to its built-in chain for the original categories (image/pdf/markdown/csv/notebook/fasta/biotable/latex/text). Binary/parse-heavy formats decode in **standalone Python helpers** under `server/src/helpers/` (`anndata_helper.py`, `chem_helper.py`, `structure_helper.py`, `massspec_helper.py`, `arrays_helper.py`, `imaging_helper.py`). They run in a dedicated **uv-managed helper venv** (`server/src/helpers/pyproject.toml`, `.venv`), resolved via `helperPython()` and pre-warmed by `syncHelperVenv()` (`server/src/helpers-env.ts`) at `prep`/boot. A generic dispatcher (`server/src/api/sci-helpers.ts`, `sciHelperFor`/`runSciHelper`) routes a `kind` param to a helper's `summarize`/`render` subcommands over two endpoints: `GET /sandbox/sci-summary?path=&kind=` (JSON) and `GET /sandbox/sci-render.png?path=&kind=&index=&axis=` (image); all helpers share the exit-code contract `0` ok / `3` deps-missing / `4` not-found / `5` bad-value / `1` other, mapped to HTTP by the routes. 3D structures also use a client-side WebGL viewer (3Dmol.js) and spectra use chart.js. New scientific viewers are view-only; user-facing coverage is in `docs/file-previews.md`.

## Office preview and editing

`server/src/api/office.ts` serves project-scoped `GET /sandbox/office` previews and `GET/PUT /sandbox/office/content` binary snapshots/saves. The existing helper venv validates bounded OOXML packages with DTD/entity rejection. Saves require an SHA-256 `If-Match` revision, recheck before atomic replacement, and record user provenance. Signed/enforced-protected documents cannot be overwritten.

`office-viewer.tsx` offers lightweight DOCX (sanitized docx-preview iframe), PPTX (Office Kit passive SVGs), and XLSX (existing arraydata viewer) previews. **Edit in Office** opens `/office?path=…&project=…` in a separate tab with `office-workspace.tsx`. The full Writer/Calc/Impress engine runs in browser WASM, without Docker. `office-toolbar.tsx` supplies Kady-themed controls with live UNO command status; native chrome is hidden by the frame layout manager and restored by All tools. Theme changes affect application colors, never document formatting; do not apply CSS filters to the canvas. Calc formula-bar drafts must commit through `.uno:EnterString` (`StringName`) before export; export-started messages establish the saved modification generation. `/office` alone uses COOP/COEP. `public/office/runtime.js` and `thread.js` bridge the virtual filesystem and UNO to revision-checked Kady saves; window messages must match source and origin. Keep macros and external update execution disabled. Do not replace native editing with text-run forms. Native Office export reserializes OOXML, so never promise byte-preservation of advanced objects.

`/office-assets/[build]/[file]` caches an allowlisted, SHA-pinned official ZetaOffice runtime snapshot in `~/.kady/office-assets/<build>/` (`KADY_OFFICE_ASSETS_DIR` overrides). Manifest updates require real browser open/edit/save checks for all three formats. Never float executable runtime assets without integrity checks. Fixture generation instructions live in `server/test/fixtures/office/generate.py`; scope and compatibility limits are in `docs/file-previews.md`.
