# Skills, prompt templates, slash commands

- **Skills.** Two scopes: per-project `sandbox/.pi/skills/` and user-level `<agentDir>/skills/` (`~/.kady/pi-agent/skills`), both loaded by Pi — the latter also reaches subagent child processes. Pi resolves project entries first and skill-name collisions are first-wins, so **a project skill shadows a global one**; the Settings list labels that. Every origin is fetched through the bundled **`skills` CLI** (vercel-labs/skills) by `server/src/agent/skills-fetch.ts`, which downloads into a disposable staging cache (`KADY_SKILLS_CACHE_DIR`, default `~/.kady/skills-cache`) shaped as `.pi/skills/<name>/` because `-a pi --copy` targets exactly our layout. The CLI is a **fetcher only** and its stdout is never parsed (truth = the staged tree + `skills-lock.json`); `skills-sync.ts` remains the sole writer of live skill dirs, so tree hashing, the default-disabled policy, atomic per-skill replacement, local-edit preservation and archive-on-removal all survive unchanged. Catalogue seeding falls back to a shallow `git clone` if the CLI fails, since it is on the first-run path. The catalogue (`KADY_SKILLS_REPO`, default `K-Dense-AI/scientific-agent-skills`, merged with the named skills of `CATALOGUE_EXTRA_SOURCES` in `config.ts` — currently `docx`/`pdf`/`pptx`/`xlsx` from `anthropics/skills`; a later source wins a name clash, the fetch is all-or-nothing so a failed source cannot read as upstream removals, and such skills record `source` on their catalogue manifest entry) syncs at launch and daily (`KADY_SKILLS_SYNC_INTERVAL_MS`, min 60s) and is **project-scoped only**. Manifest v2 (`.kady/skills-sync.json`, migrated from v1 rather than discarded) adds a per-skill `origin` (`catalogue`/`registry`/`local`) plus recorded source/ref, a content `catalogueDigest` replacing the commit id (staging is not a checkout), and `removed` tombstones so deleting a catalogue skill isn't undone by the next sync. `skills-install.ts` owns preview→install (the confirmed preview returns a `stagingToken` so the user installs the bytes they reviewed; the acknowledgement is enforced server-side), authoring from a template with Pi's stricter name rule, in-place `SKILL.md` editing, origin-aware removal, and on-demand update checks — user-installed skills are **never** auto-updated. Routes live in `server/src/api/skills.ts` (`?scope=project|global`); `GET /skills` merges both scopes for the composer picker so it agrees with what the agent loads. UI: `web/src/components/skills-panel.tsx`. See `docs/skill-management.md`. Live sessions keep their already-loaded skill set.
    **Prompt templates + slash commands.** `/skill:<name> args` and `/<template> args` on the first line of a chat message are expanded by Kady, not Pi (`server/src/agent/prompt-expansion.ts`, ports of Pi's `parseCommandArgs`/`substituteArgs` plus "append unused args"), read fresh from disk (project entries win), and `session.prompt()` is called with `expandPromptTemplates: false`; `/steer` and `/follow-up` expand too. The skill block is byte-identical to Pi's so `parseSkillBlock` works; templates expand to `<prompt-template name=…>`, and the web `command-blocks.ts` renders both as chips. Templates live in `sandbox/.pi/prompts/*.md` and `<KADY_PI_AGENT_DIR>/prompts/*.md` (`agent/prompts.ts`, routes `api/prompts.ts`, Settings → Prompt templates; six scientific templates seeded per project, including `/prove-verify`; exact unchanged older shipped versions upgrade, while edits and deletions are preserved; a template added later is offered once to existing projects, tracked by name in `.kady/prompts-seeded-names.json` with `LEGACY_SEEDED_TEMPLATES` standing in for markers written before names were tracked). `disable-model-invocation` is exposed on `GET /skills` and toggled line-wise via `POST /skills/:name/model-invocation` (`setSkillModelInvocation`); the composer's pinned-skill picker hides such skills and the `/` menu offers them.
