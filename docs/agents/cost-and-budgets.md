# Cost ledger and budgets

- **Cost ledger + budgets.** Pi reports `usage.cost` inline (no async backfill). `server/src/cost/ledger.ts` snapshots `getSessionStats()` before/after each run and appends a row to `projects/<id>/sandbox/.kady/runs/<sessionId>/costs.jsonl` (role `agent`|`subagent`|`compute`). Pi adds tool-result `usage` to those stats, so `server/src/cost/tool-usage.ts` splits it out of the turn's row on `turn_end`: models a tool ran itself (codemode `models.generateImages()`/`models.classify()` call rows, `generate_image`'s `details.model`) get their own rows billed by **their** provider and credential — a ChatGPT-subscription turn that generates an OpenRouter image must not ledger that spend as $0 — and child usage pi-subagents aggregates onto `subagent` results is dropped because the meter/bridge already ledgered it. `server/src/cost/billing.ts` classifies OpenRouter/API-key and Anthropic OAuth usage as cap-counted, while ChatGPT/Copilot/xAI/Kimi Code/Meta subscription runs retain tokens plus `listPriceUsd` with `costUsd: 0`; provider quotas and overages remain external. Durable Modal jobs reserve a full-lifetime sandbox estimate (GPU plus CPU/RAM, with CPU/RAM limits matching the preset) before admission; project summaries expose spent/reserved/committed USD, and every terminal path reconciles the hold to estimated sandbox wall-time, or the full reservation when cleanup is unconfirmed. Builds, cache storage and egress are outside this estimate. A project `spendLimitUsd` blocks only cap-counted work when the new commitment would exceed the cap.
