# CODING_STANDARDS.md

Coding standards and review-time rules for this repository, linked from `AGENTS.md`. Subsystem invariants live in `docs/agents/*.md` (see the rules index there); this file holds the rules that apply when writing or reviewing any non-trivial change.

## Toolchain

- **Don't run our source through `tsc` for emit** — both dev and prod run via `tsx`; `tsconfig.json` is `noEmit` for typechecking only.

- **Node ≥ 22.19** is what Pi targets; lower 22.x usually works but emits an `EBADENGINE` warning. Node < 22 (e.g. v20) fails to build/install the packages, so the launcher (`start.mjs`) refuses to run on it, on every platform.

- **Windows portability.** Sandbox-relative paths are canonicalized to forward slashes at the API boundary (`apiRelative`/`toApiPath` in `server/src/sandbox-fs.ts`, `stripSandboxRoot` in `server/src/agent/events.ts`) — the frontend always sees `/`-separated paths. External binaries are located via `server/src/binaries.ts` (`hasBinary`/`findUv`/`firstRunnable`), never `which`. On Windows the agent's `bash` tool uses Git Bash (Git for Windows is a hard prerequisite there), the helper venv interpreter lives at `.venv/Scripts/python.exe`, and synctex is invoked from the PDF's directory with relative paths so drive-letter colons stay out of its colon-delimited args in the primary invocation (`forwardArgs`/`inverseArgs` in `server/src/latex/synctex.ts`; a forward-slash absolute-path retry exists as a fallback for absolute `Input:` records).

## Pinned harness

- **The harness is pinned to exact versions.** `server/package.json` pins Pi (`@earendil-works/pi-{agent-core,ai,coding-agent}`, which share a version line) and the extension packages `pi-subagents`, `pi-web-access`, and `skills` to exact versions (no caret). `installBackendPackages()` in `start.mjs` reads those pins and installs them as explicit `name@version` specs on every full start, so a checkout with a stale or hand-edited lockfile still converges on the pinned set. Upgrading the harness is a deliberate act: bump the pins in `server/package.json` (Pi's three packages must stay on one version), run `npm install` in `server/` to move the lockfile, and re-run typecheck + tests before shipping — the `workflowScript` and builtin-tool-override caveats above are the class of upstream change that breaks silently if versions float. Bump `pi-subagents`/`pi-web-access` with Pi: both track Pi's extension APIs closely (pi-subagents < 0.68 bundled a Pi-0.85-only `pi-server`). Since Pi 0.86 both packages start fresh sessions with a lazy loader tool (`subagents_enable`, `web_enable`) instead of their full tools; the lead's `tools` allowlist omits the loaders, and when a loader is filtered out each package keeps its tools eager (verify with `session.getActiveToolNames()` after an upgrade). Children carry no allowlist, so `ensureWebAccess` seeds `toolActivation: "eager"` into `<agentDir>/web-search.json` (write-if-missing; both packages default to `"auto"` since pi-web-access 0.34 / pi-subagents 0.74), together with scientific `summaryInstructions` (pi-web-access 0.35, used by `auto-summary`; `SCIENTIFIC_SUMMARY_INSTRUCTIONS`; a blank string keeps the package default). `seedSubagentRuntimeSettings` also seeds pi-subagents' `disabledFeatures: ["panes", "external-machines"]` (write-if-missing) — TUI panes and Herdr machines have no Kady surface, and the tool declaration rides every lead request. It also seeds `activeRunsPrompt: true` (0.78, write-if-missing; an explicit `false` sticks): launches default to async and chats are long-lived, so the lead's system prompt lists its queued/running background runs until they finish instead of relying on completion notices to remember them. The lead excludes both loaders by name (`LEAD_EXCLUDED_TOOLS`, see the MCP caveat for why it is a denylist). Current pins: Pi 1.3.0, pi-subagents 0.78.0, pi-web-access 0.41.0, skills 1.7.0. Since Pi 1.2, `before_agent_start` also fires for runs an idle `triggerTurn` custom message starts (`event.messageType: "custom"`, no `prompt`), so Kady's prompt-section handlers now reach system runs too; a handler meant only for user prompts must check `messageType === "user"`. Pi 1.2 also made OpenRouter's saved list in `<agentDir>/models-store.json` replace the built-in catalog regardless of age (1.0 preferred whichever was newer); Kady never refreshes catalogs at boot, so `pruneStaleOpenRouterCatalog` (`models.ts`, called before `ModelRuntime.create`) drops a list saved before the installed catalog — otherwise a pre-upgrade cache keeps pricing the lead and every child from stale data.

Upgrading the harness is a deliberate act; the paragraph above is the procedure and its checks. The `workflowScript` and builtin-tool-override caveats it refers to as "above" are the delegation rules in [docs/agents/subagents.md](docs/agents/subagents.md).

## Duplicates that must stay in sync

When either side of one of these pairs changes, update both and keep the parity test green:

- Fusion pricing — `JUDGE_CALLS_PER_TURN` and the judge accessor exist in `server/src/agent/models.ts` and `web/src/lib/fusion-presets.ts` (`server/test/fusion-pricing.test.ts`); see **Fusion pricing** in [docs/agents/models-and-providers.md](docs/agents/models-and-providers.md).
- Bash classifier — `server/src/agent/bash-classifier.ts` is copied byte-for-byte into `server/pi-packages/kady-guard/classifier.ts` (`bash-classifier.test.ts` asserts parity); see **Raw-data guard** in [docs/agents/security.md](docs/agents/security.md).
- Notebook schemas — `server/src/agent/notebook.ts` and `server/pi-packages/kady-notebook/index.ts` are deliberate duplicates guarded by a parity test; see **Living Lab Notebook (`notebook`)** in [docs/agents/notebook.md](docs/agents/notebook.md).
- Local-model billing — `local`/$0 must appear in `cost/billing.ts`, `cost/ledger.ts`, and `agent/subagent-bridge.ts`, or a local run defaults to `payg` and counts against the spend cap; see **Local model servers** in [docs/agents/models-and-providers.md](docs/agents/models-and-providers.md).
- Shared notebook semantics — `web/src/lib/notebook-evidence-core.ts` is imported by the server too; keep it IO/framework-free and inside web's Turbopack root; see **Evidence-aware notebook** in [docs/agents/notebook.md](docs/agents/notebook.md).

## Review-time checks

- New browser-loaded URLs (`<img>`, downloads, pdf.js) go through `withApiToken()`, and side-effecting routes are never GETs — [docs/agents/security.md](docs/agents/security.md).
- Tests that build a `ProvenanceRecorder` pass `captureEnvironment: false` or a stub — [docs/agents/provenance.md](docs/agents/provenance.md).
- The lead's tool denylist (`LEAD_EXCLUDED_TOOLS`) must never name `bg_wait`, and MCP registration forces the denylist shape (`excludeTools`, not `tools`, with the `defaultTools` override applied after `resourceLoader.reload()`) — [docs/agents/subagents.md](docs/agents/subagents.md), [docs/agents/mcp.md](docs/agents/mcp.md).
- `staging/outputs` under a Modal job directory is the retained, verified copy that evidence packages and robustness workflows read — never prune it — [docs/agents/modal-compute.md](docs/agents/modal-compute.md).
- Seed-once markers (`LEGACY_SHIPPED_HASHES`, `LEGACY_SEEDED_ROSTER`, `LEGACY_SEEDED_TEMPLATES`) stand in for older markers and are never extended — [docs/agents/subagents.md](docs/agents/subagents.md), [docs/agents/skills.md](docs/agents/skills.md).
